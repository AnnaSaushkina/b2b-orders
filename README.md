## Демо: B2B-платформа управления дистрибуцией и заказами

**Стек:** React · TypeScript · TanStack Query · Webpack · NestJS · Prisma · PostgreSQL · FSD · Docker

### Демо

**[Открыть каталог](http://157.22.231.139/b2b-orders/)** — 50 000 позиций в базе, в DOM держится
~12 узлов. Прокрутите список: карточки разной высоты, следующая страница подгружается по
достижении конца, скролл не проседает.

Что смотреть в коде:
[`VirtualList`](client/src/shared/ui/virtual-list/index.tsx) — сам компонент ·
[`products-list`](client/src/pages/products-list/index.tsx) — подключение и пагинация ·
[`fetchProducts`](client/src/entities/product/api/index.ts) — отмена устаревших запросов

### Задача

Менеджер дистрибьютора собирает заказ из каталога в 50 000 позиций и работает с ними одним
списком. Полный рендер каталога вешал страницу: браузер держал 50 000 DOM-узлов, скролл шёл
рывками. Нужно было открыть весь ассортимент без деградации интерфейса.

### Ключевые технические решения

- **Виртуализация каталога с динамическим замером высоты** — в DOM держится только видимое
  окно. **~12 DOM-узлов вместо 50 000**. Карточки товаров разной высоты (число характеристик
  отличается), поэтому высота не считается как «индекс × константа», а измеряется у реальных
  узлов после рендера и уточняет оценку.
- **Серверная offset-пагинация с бесконечным скроллом** (NestJS + Prisma + PostgreSQL) —
  данные грузятся порциями по 200 по мере скролла, а не все 50 000 сразу: быстрый первый
  экран, меньше нагрузки на сеть и память.
- **Data-layer на TanStack Query** — `useInfiniteQuery` с отменой устаревших запросов через
  `AbortSignal` при быстром скролле: устранена гонка запросов (видно `(canceled)` в Network),
  стоп-условие пагинации через `getNextPageParam`.
- **Деньги в копейках целым `Int`** — суммы никогда не живут во float, форматирование
  (`Intl.NumberFormat`) только на выводе. Обход накопления ошибки IEEE 754.
- **Переиспользуемый generic-компонент `VirtualList<T>`** — развязан от доменного типа через
  констрейнт `T extends ItemWithId`, `shared` ничего не знает о товарах.
- **FSD-архитектура** — app / pages / widgets / features / entities / shared.

### Почему не «просто взять библиотеку»

Виртуализация сначала была написана вручную: окно от `scrollTop`, overscan, абсолютное
позиционирование со spacer'ом. Реализация работала на элементах фиксированной высоты и
упёрлась в динамическую: позиция элемента перестаёт быть `индекс × константа`, нужен
накопленный массив смещений с пересчётом после замера каждого узла.

Решение принято в пользу `@tanstack/react-virtual` — эта математика не является предметом
разработки продукта, а её ручная поддержка стоит дороже, чем даёт. Ручная реализация
сохранена в истории (`git show 4bc5e66:client/src/shared/ui/virtual-list/index.tsx`):
она объясняет, что именно библиотека делает внутри.

### Запуск

Требуется Node 22+, pnpm, Docker.

```bash
# 1. переменные окружения
cp .env.example .env

# 2. инфраструктура (PostgreSQL + Redis) в контейнерах
docker compose up -d

# 3. зависимости
pnpm install

# 4. схема БД + тестовые данные (50k товаров)
cd server && npx prisma migrate deploy && npx tsx prisma/seed.ts && cd ..

# 5. клиент + сервер одной командой
pnpm dev
```

Клиент — `http://localhost:3000`, API — `http://localhost:4000`.

Полностью в контейнерах (API + инфраструктура):

```bash
docker compose -f docker-compose.yml -f docker-compose.app.yml up -d --build
```

Внутри сети compose API ходит в базу по имени сервиса (`postgres:5432`), а не по `localhost`.
Подробности — в [docs/DOCKER.md](docs/DOCKER.md).
